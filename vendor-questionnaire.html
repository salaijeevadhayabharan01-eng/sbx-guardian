2. Data Security Controls
2.1 Is data encrypted at rest?
YESAll sensitive data fields are encrypted at rest using AES-256-GCM with unique initialization vectors per record. Event logs additionally protected by SHA-256 cryptographic hash chain providing tamper evidence.
2.2 Is data encrypted in transit?
YESAll data transmitted to and from SBX Guardian is encrypted using TLS 1.2 or higher. HTTPS is enforced on all endpoints. Webhook payloads, API calls, and dashboard traffic are encrypted in transit.
2.3 Is multi-tenant data isolation implemented?
YESRow-level security is enforced at the application layer on every database query using organization ID. No cross-tenant data access is architecturally possible. JWT tokens are organization-scoped preventing horizontal privilege escalation.
2.4 Is multi-factor authentication (MFA) supported?
ROADMAPMFA is on the 2026 product roadmap. Currently: strong JWT authentication, webhook secret authentication, API key management with SHA-256 hashing. Enterprise clients may request accelerated MFA delivery.
2.5 Is Single Sign-On (SSO/SAML 2.0) supported?
ENTERPRISESSO/SAML 2.0 is available on the Enterprise plan. Contact enterprise@sbxguardian.com for implementation details and timeline.
2.6 Are access logs and audit trails maintained?
YESComprehensive audit trail logs every action with: user identity, timestamp, IP address, resource, and action type. Audit logs are tamper-evident and append-only. Account admins can export audit logs at any time.
2.7 How are API keys and secrets managed?
YESAPI keys are stored as SHA-256 hashes (never in plain text). Webhook secrets are cryptographically random 256-bit values. Keys can be rotated at any time from the dashboard. Old keys are immediately invalidated upon rotation.
2.8 What rate limiting is implemented?
YESRate limiting is applied per-endpoint: Authentication endpoints: 30 req/15 min. Webhook ingestion: 1,000 req/15 min. General API: 1,000 req/15 min. Per-user rate limiting applies on sensitive operations.

4.1 Is there a documented incident response plan?
YESIncident response plan covers: detection, classification, containment, eradication, recovery, and post-incident review. Clients are notified within 72 hours of any personal data breach (48 hours for Enterprise). Available on request.
4.2 What is the RTO and RPO?
YESRecovery Time Objective (RTO): 4 hours. Recovery Point Objective (RPO): 6 hours (automated backup frequency). Enterprise clients receive enhanced SLAs with 99.9% uptime commitment and dedicated incident response.

5. Privacy & Data Handling
5.1 Where is customer data stored geographically?
DOCUMENTEDData stored on Render.com infrastructure (US). EU data transfers covered by SCCs. EU-region hosting available for Enterprise clients. Sub-processor list maintained at trust-center.html.
5.2 Is customer data used to train AI models?
NOCustomer data is never used to train AI models — ours or third-party providers. AI report generation sends data to Groq/Gemini for inference only; per their terms, this data is not used for training. Contractually confirmed.
5.3 What is the data retention policy?
YESMinimum 6-month retention for event logs (EU AI Act Art. 12 requirement). Configurable longer retention available. On account deletion: data anonymized within 30 days, permanently deleted within 90 days. Legal hold available on Enterprise.
5.4 Does the company support GDPR data subject rights (access, deletion, portability)?
YESAll GDPR rights supported: Data export (JSON) available from dashboard Settings → GDPR Export. Account deletion available from Settings → Delete Account. Data subject requests responded to within 30 days as required by GDPR Art. 12.
5.5 Is there a responsible disclosure / vulnerability disclosure program?
YESResponsible disclosure program active. security@sbxguardian.com — 48-hour acknowledgment commitment, 90-day coordinated disclosure. security.txt available at /.well-known/security.txt.
6. AI-Specific Security Controls
6.1 What AI systems are used in the platform?
DOCUMENTEDGroq (LLaMA 3.3 70B) and Google Gemini 1.5 Flash — used for AI report generation only, on explicit user request. No autonomous AI decision-making affects platform security or data handling. AI usage is logged in the audit trail.
6.2 How is prompt injection prevented?
YESAI inputs are sanitized and prefixed with system prompts establishing context boundaries. User data is separated from instruction data in all AI API calls. AI outputs are parsed and validated before storage or display.
6.3 Is the platform itself compliant with the EU AI Act?
YESSBX Guardian's own AI usage follows EU AI Act principles: transparency (users know AI generates reports), human oversight (all AI reports are clearly labeled and must be reviewed by humans), and data minimization.
